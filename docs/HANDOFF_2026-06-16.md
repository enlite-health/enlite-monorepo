## 1. O que foi FEITO

### 1.1 Thread do recrutamento (Javier) — fechada
- **Pergunta:** ATs subindo "Constancia de Monotributo" no campo "Registro Profesional"; e permissões para editar perfis.
- **Diagnóstico (DBA + código):** `professional_registration` e `monotributo_certificate` são **slots distintos**. O slot Monotributo só renderiza quando `profession === 'AT'`. Em prod, **68% dos workers têm `profession = NULL`** → nunca veem o slot → sobem no campo visível mais próximo. Não é alias; é **dado faltante**.
- **Permissões:** a ausência de edição de perfil pelo operador é **PROPOSITAL** (força o recrutamento a contatar o worker p/ completar cadastro). Edição futura só em nível **Super Admin**.
- **Entregue:** resposta pronta em ES para o Javier + `DP-002` no FOLLOWUPS.

### 1.2 Feature em produção: contact-notes + coluna "Confirmados"
- **WJA Contact Notes** (registro de eventos/mensagens de contato AT×Vaga) — domínio, use cases, repo, controller, migration 204, modal no funil.
- **Coluna "Confirmados"** na lista de vacantes + coluna **"NOTAS"** no funil.
- Cobre itens do backlog da semana. Mergeado via **PR #47**.

### 1.3 TD-051 — RESOLVIDO (16 suites E2E)
- A `main` tinha **16 suites E2E quebradas** por *fixture drift* (fixtures escritos antes de constraints/triggers das migrations 183/191/194 + UNIQUE do ADR-001). Isso **bloqueava todo merge**.
- Corrigido: workers `status='REGISTERED'`, stages válidos pós-194, encuadres com `ON CONFLICT (worker_id, job_posting_id)`, `$N::uuid::text` em md5 ambíguo, expectativas `NOT_QUALIFIED→REJECTED`, seed de `content_sid`.
- **Validado local** (E2E destravado, ver §5.3) **e na CI**. `main` agora com **e2e verde**.

### 1.4 Bug de PRODUÇÃO corrigido: auto-invite
- `MatchmakingService.saveMatchResults` insere WJA com `source='system'` e inclui workers `INCOMPLETE_REGISTER` de propósito (convite p/ completar cadastro). O **trigger 183** bloqueava e **derrubava o batch inteiro** (sem catch por linha) — convites silenciosamente não saíam em prod.
- **Fix:** migration **205** adiciona `'system'` ao bypass do trigger (mesma lógica do `'talentum'`).

## 3. O que VAMOS FAZER (ABAC — decisões travadas)

**Objetivo:** sistema de controle de acesso do painel `/admin`, com fundação **multi-tenant** e **Cerbos** como engine, feito **completo** (zero-followup, 100% cobertura).

**Decisões travadas:**
- **D1** multi-tenant: fundação infra+backend agora (filtro app-level; isolamento full do domínio é roadmap Fase 7).
- **D2** Cerbos é o engine (via `permissions[]` no JWT — sem Admin API sync).
- **D3** matriz recurso×ação montada do zero (18 recursos), pensada p/ propagação fácil.
- **D4** modular monolith em `worker-functions/src/modules/identity/permissions/`, pronto p/ extração (permission-service MS#8).
- **D5** EnliteRole é camada base; grupos são a camada acima.
- **D6** 100% cobertura é gate de fechamento.
- **Escopo:** ABAC **só `/admin`**; app do worker fora.

**Sign-offs já dados (Gabriel):** Super Admin = grupo de sistema (membros: gabriel.stein@, diego.trevisan@enlite.health, gestão fácil via UI); `PENDING_ONBOARDING` = acesso zero (só onboarding); grupo "Financeiro" adiado; recurso = `funnel`/`wja` (nunca `encuadre`).

Sequência de build do `02-architecture.md`:

1. **Migration schema IAM** (bloqueante): `tenants` + `tenant_id` nas tabelas IAM + `users.status` enum + `permissions` (seed 18 recursos) + `permission_groups` + `group_permissions` + `user_groups` + `user_departments` + `permission_audit_log` + função `get_user_effective_permissions()` + seed dos 5 grupos de sistema + auto-assign por role.
2. **Domain + ports** (paralelo com 3): estender `Auth.ts` (ResourceType/Action), criar `Permission.ts`.
3. **Infra backend** (paralelo com 2): `PermissionRepository`, ajustar `CerbosAuthorizationAdapter` (`permissions[]` no payload).
4. **Application**: `GetEffectivePermissionsUseCase`, `AssignUserToGroupUseCase`, `ManageGroupUseCase` (anti-lockout), `SyncPermissionClaimsUseCase`.
5. **Login**: estender `GetAdminProfileUseCase` (emitir `permissions[]` + `tenant_id` nos claims, try/catch + fallback).
6. **Interface**: `PermissionController` + rotas; **split do `AuthMiddleware`** (>400 linhas) → `PermissionMiddleware` com `requirePermission`; ligar Fase A (`USE_GROUP_PERMISSIONS`).
7. **Cerbos** (paralelo): Cloud Run `enlite-cerbos` + policies YAML por recurso.
8. **Frontend**: corrigir bug `CerbosAuthorizationRepository` (`roles:[]`), `adminAuthStore` (+permissions), `usePermissions`, `PermissionGate` (grep callers antes — breaking), `PermissionsPage`.
9. **Ligar Cerbos** (`USE_CERBOS=true`) rota a rota, **E2E de DENY antes de cada**.
10. **Testes 100%** + fechamento.

> **Gate duro (zero-followup):** todo bug/incompletude do escopo é resolvido+testado no build, não vira TD. Itens fora de escopo (isolamento full por tenant = Fase 7; ABAC camada DATA = Fase 8) são roadmap comprometido, não débito.
